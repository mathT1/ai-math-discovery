## 2. 기술 스택과 선택 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 호스팅 | GitHub Pages (정적) | R2·R3 충족, 비용 0, 서버·DB 없음 → 개인정보 위험 없음 |
| 화면 | **순수 HTML + CSS + JavaScript(ES 모듈), 빌드 도구 없음** | 교사 1명이 유지보수 가능. npm·프레임워크 버전 문제가 없음. 파일을 열면 바로 고칠 수 있음 |
| 그림 | Canvas / SVG 직접 사용 | 격자·행렬 정도는 라이브러리가 필요 없음 |
| 수식 | KaTeX (**저장소에 파일 포함**, CDN 사용 안 함) | 학교망 CDN 차단 대비, 오프라인 동작 |
| 계산 | JavaScript만 사용. **Pyodide 사용 안 함** | Pyodide는 첫 로딩이 수십 MB라 학교 Wi-Fi·크롬북에서 느림. MVP 계산(공선 판정, 행렬 곱)은 정수 연산이라 JS로 충분 |
| 논문 결과 | `data/*.json`에 미리 저장 | 브라우저에서 AI 모델을 돌리지 않음 (BRIEF 5-1) |
| 모듈 목록 | GitHub Actions가 배포 때 `modules/*/module.json`을 모아 `modules/index.json` 생성 | 정적 사이트는 폴더 목록을 읽을 수 없음. 이렇게 하면 "폴더 추가만으로 자동 반영"(R6)이 됨 |
| 오프라인 | Service Worker (2차 마일스톤, 선택) | 한 번 열면 동작. MVP 필수는 아님 |
| 외부 스크립트 | 없음 (분석·광고·폰트 CDN 금지) | BRIEF 5-2 |

## 4. 모듈 표준

### 4-1. 모듈 폴더

```
modules/<id>/
  module.json     # 메타데이터
  index.html      # 활동 화면 (core/ 를 import)
  activity.js     # 활동 로직
  grader.js       # 자동 채점 함수 (rubric.json이 이름으로 참조)
  schema.json     # 결과물 형식
  rubric.json     # 평가 기준
  guide.md        # 교사용 지도안
  data/           # 논문 결과 데이터 + 출처 표기
```

BRIEF 초안에 `activity.js`, `grader.js`를 더함. 채점 규칙을 JSON 안의 수식 문자열로 쓰면 `eval`이 필요해져 위험하고 디버깅도 어려움. 모듈 폴더 안의 함수로 두면 본체 코드는 고치지 않아도 됨.

### 4-2. module.json (BRIEF 초안에 추가할 필드)

```json
{
  "id": "no-three-in-line",
  "version": "1.0.0",
  "status": "published",
  "title": "세 점이 한 직선 위에 놓이지 않게",
  "summary": "격자에 점을 최대한 많이 찍되, 세 점이 한 직선 위에 오면 안 된다.",
  "subject": "공통수학2",
  "unit": "도형의 방정식",
  "topics": ["기울기", "공선", "경우의 수"],
  "achievement_standards": ["확인 필요"],
  "grade": ["고1"],
  "periods": 1,
  "difficulty": 2,
  "paper": { "title": "...", "url": "...", "code": "...", "license_note": "데이터 출처·라이선스" },
  "output_schema": "schema.json",
  "rubric": "rubric.json",
  "teacher_guide": "guide.md",
  "authors": ["동규"]
}
```

- `version`: 결과물 JSON에 함께 기록. 루브릭이 바뀌어도 예전 제출물을 구분할 수 있음.
- `status`: `draft`는 홈에 안 보임. 만들다 만 모듈이 배포돼도 안전함.

### 4-3. 결과물 JSON (모든 모듈 공통 겉포장)

```json
{
  "format": "ai-math-result/1",
  "module": { "id": "no-three-in-line", "version": "1.0.0" },
  "student": { "name": "홍길동", "class": "1-3", "number": 12 },
  "created_at": "2026-11-05T10:20:00+09:00",
  "payload": { "...모듈별 내용, schema.json으로 검사..." },
  "checksum": "sha256:..."
}
```

- 체크섬: `payload`+`module`+`student`를 정해진 순서로 직렬화한 값의 SHA-256 (브라우저 내장 Web Crypto, 라이브러리 없음).
- 의미: "파일을 손으로 고쳤는지" 표시만 함. 위조를 막지는 못한다고 지도안에 적음.

### 4-4. rubric.json

```json
{
  "scale": ["A", "B", "C", "D", "E"],
  "items": [
    { "id": "valid", "label": "규칙을 지킨 배치", "type": "auto", "fn": "checkValid", "max": 2 },
    { "id": "count", "label": "점의 개수", "type": "auto", "fn": "scoreCount", "max": 3 },
    { "id": "explain", "label": "공선 판정 방법 설명", "type": "teacher", "max": 5,
      "levels": { "5": "기울기 비교를 식으로 설명", "3": "예시로만 설명", "1": "설명 없음" } }
  ],
  "level_cut": { "A": 9, "B": 7, "C": 5, "D": 3 }
}
```

- `auto`: `grader.js`의 함수 이름. 학생 JSON을 받아 점수와 근거 문장을 돌려줌.
- `teacher`: 평가 페이지에 입력 칸으로 나타남. 교사가 점수를 고름.
- 자동 채점은 학생이 낸 값을 그대로 믿지 않음. 예: 점 좌표를 받아 **공선 여부를 다시 계산**함.

## 5. 결과물 다운로드 형식과 평가 흐름

**학생**
1. 활동 시작 때 이름·반·번호 입력 (기기 밖으로 전송 안 함, 저장소에도 안 남김).
2. 활동 → AI 결과와 비교 → 정리 질문 답 작성.
3. [결과물 받기] → 파일 2개: `<모듈>_<반>-<번호>_<이름>.png`(보고서), `.json`(채점용).
4. 학교 경로(Q4)로 둘 다 제출.

**교사** (`teacher/index.html`, 모든 처리는 교사 브라우저 안에서)
1. 모듈 선택 → JSON 여러 개 끌어다 놓기 (zip 일괄 업로드는 2차).
2. 형식 검사, 체크섬 확인, 같은 학생 중복 제출 표시.
3. 자동 항목 채점 + 근거 표시 → 교사 항목 입력.
4. CSV 다운로드 (UTF-8 BOM 포함 → 엑셀에서 한글이 안 깨짐).

PNG 보고서 내용: 학생 정보, 활동 결과 그림, 핵심 수치, 정리 질문 답, AI 결과와의 비교 한 줄, 생성 시각.

## 7. 모듈별 상세 설계

### 7-1. `no-three-in-line` (1순위 권장)

- **학습 목표**
  1. 세 점이 한 직선 위에 있는지 기울기(또는 넓이 0)로 판정할 수 있다.
  2. 조건을 만족하는 배치를 찾고, 한 행에 점이 최대 2개라서 최대 개수가 2n 이하인 이유를 설명할 수 있다.
  3. 사람의 탐색과 AI 탐색의 차이를 말할 수 있다.
- **성취기준**: 확인 필요 (공통수학2 도형의 방정식 — 직선의 방정식 관련 성취기준 후보. NCIC 원문으로 코드 확인 후 기입)
- **활동 흐름 (1차시)**
  1. 도입: 3×3, 4×4에서 손으로 시도
  2. 탐구: n 선택(3~10) → 점 찍기 → 공선이 생기면 그 세 점과 직선을 **선 모양과 번호로** 표시(색만 쓰지 않음)
  3. 원리: 판정식 (x₂−x₁)(y₃−y₁) = (y₂−y₁)(x₃−x₁) 을 보여줌 (정수 계산이라 오차 없음)
  4. 비교: 같은 n의 2n개 배치(data/)를 보고 자기 해와 비교
  5. 정리 질문: "왜 2n개보다 많이는 불가능할까?"
- **결과물 payload**: `n`, `points[]`, `collinear_triples[]`(다시 계산), `max_reached`, `answers{}`
- **루브릭**: 규칙 준수(자동) · 점 개수 대비 2n(자동) · 상한 2n 설명(교사) · 판정 방법 설명(교사)
- **데이터 검증**: 작은 n의 2n 배치는 sandbox에서 직접 탐색해 만들고, 논문·참고 코드 결과와 대조. 모든 데이터는 테스트로 "공선 없음"을 확인.

### 7-2. `matrix-mult` (2순위 권장)

- **학습 목표**
  1. 2×2 행렬의 곱을 계산할 수 있다.
  2. 곱셈 7번(스트라센 방법)으로 같은 결과가 나옴을 확인한다.
  3. "곱셈 횟수를 줄이는 방법 찾기"를 AI가 어떻게 게임처럼 풀었는지 설명할 수 있다.
- **성취기준**: 확인 필요 (공통수학1 행렬의 곱셈 관련)
- **활동 흐름 (1~2차시)**
  1. 일반 방법: 곱셈 8번 직접 세기
  2. 퍼즐: 스트라센 식 M₁~M₇ 조각을 끌어다 C의 네 성분을 만들기 → 아무 숫자 행렬로 즉시 검산
  3. 확장 이야기: 큰 행렬로 갈수록 차이가 커짐(직관만), AlphaTensor가 찾은 4×4(mod 2) 결과 소개 — 수치는 논문 원문으로 확인 후 기입
  4. 정리 질문: "덧셈은 늘었는데 왜 이득일까?"
- **결과물 payload**: 조립한 식, 검산 결과(무작위 행렬 여러 개), 사용한 곱셈 수, `answers{}`
- **루브릭**: 식의 정확성(자동, 기호 계산 대신 무작위 정수 행렬 여러 개로 검산) · 곱셈 수(자동) · 이득 설명(교사)
- **주의**: R7 — 계산 복잡도 지수(log₂7)는 "보충 설명"으로만.

### 7-3. 나머지 후보에 대한 의견 (MVP 제외 이유)

| 모듈 | 의견 |
|---|---|
| `colored-plane` | 매력적이지만 "평면 색칠 수 5~7" 같은 결과 설명이 고교 범위를 넘기 쉬움. 2차 |
| `continued-fraction` | 수열의 극한이 2022 개정에서 어느 과목인지 확인 필요(미적분Ⅱ로 추정). 고2~3용으로 2차 |
| 2순위 5편 | 융합·동아리용. 모듈 표준이 안정된 뒤 추가하며 표준을 검증하는 용도로 적합 |

## 10. GitHub 배포·버전 관리

- 공개 저장소, 기본 브랜치 `main` → push 시 Actions가 `build-index.mjs` 실행(검사 실패 시 배포 중단) 후 Pages 배포.
- 작업은 브랜치 + PR. 혼자 작업해도 PR로 변경 기록을 남김.
- 플랫폼 버전은 태그(`v1.0.0`), 모듈은 `module.json`의 `version`.
- 수업 학기 중에는 이미 쓰는 모듈의 `schema`를 깨는 변경 금지 (새 버전으로 추가).

## 11. 새 모듈 추가 절차 (기여 가이드 초안)

1. `modules/_template/`를 복사해 `modules/<id>/`로 이름 바꾸기 (`status: "draft"`).
2. `module.json` 작성. 성취기준은 확인된 코드만, 아니면 "확인 필요".
3. `activity.js`에 활동 작성, `core/export.js`로 결과물 내보내기.
4. `schema.json`, `rubric.json`, `grader.js` 작성.
5. `guide.md`: 차시 흐름, 발문, 예상 오개념, 수학적 사실의 출처표.
6. `node tools/build-index.mjs`로 검사 → 로컬에서 확인.
7. PR 생성 → 검토 → `status: "published"`로 바꿔 병합.

본체(`core/`, 홈, 평가 페이지)는 건드리지 않는다. 건드려야 한다면 그건 표준의 빈틈이므로 이슈로 따로 기록.

## 13. 위험 요소와 대응

| 위험 | 대응 |
|---|---|

## Antigravity와 논의하고 싶은 쟁점 (예상)

1. 빌드 도구(Vite 등) 사용 여부 — Claude는 "사용 안 함" 쪽.
2. 자동 채점 규칙을 JSON 선언형으로 할지, 모듈별 `grader.js`로 할지.
3. Pyodide 필요성 — Claude는 MVP에서 불필요하다고 봄.
4. MVP 두 번째 모듈: `matrix-mult` vs `continued-fraction` vs `colored-plane`.
