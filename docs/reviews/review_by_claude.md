## 2. 우려되는 점 (근거 포함)

### C1. 성취기준을 "검증 완료"로 적음 — BRIEF 4절 규칙 위반 위험 **[중요]**
- 초안 7-1, 7-2절에 `[10공수2-01-02]`, `[10공수1-03-01]`, `[10공수1-04-02]`를 "검증 완료"로 적었으나 **출처(문서명·쪽)가 없음**.
- 7-2의 "성취기준 해설: 행과 열의 수가 각각 2를 넘지 않는 범위"도 인용 출처가 없음.
- Claude가 웹 검색으로 확인을 시도했으나 원문을 찾지 못했음 (1단계 기록).
- BRIEF: "확인 못 한 코드는 지어내지 말고 '확인 필요'로 표시할 것."
- 같은 문서 7-3에서는 `continued-fraction`을 "미적분I 수열의 극한"으로 적었는데, 2022 개정에서 수열의 극한이 어느 과목에 있는지도 확인이 필요함.

### C2. 예시 데이터에 수학 오류 **[중요]**
- 4-2절 예시의 6×6 배치(12개 점, `collinear_violations: 0`)를 검사하니 **일직선 위의 세 점이 4쌍** 있음:
  - (0,1)(1,2)(2,3) · (0,4)(1,2)(2,0) · (3,2)(4,3)(5,4) · (3,5)(4,3)(5,1)
  - 검사: 정수 판정식 (x₂−x₁)(y₃−y₁) = (y₂−y₁)(x₃−x₁), 모든 3점 조합(220개) 확인.
- 이 예시가 그대로 템플릿·테스트 데이터로 쓰이면 정답 아닌 배치가 정답으로 퍼짐.
- 이 오류가 C3의 근거이기도 함: **학생 파일에 적힌 "위반 0"을 믿으면 틀린 배치도 만점**이 됨.

### C3. 자동 채점이 학생이 적은 값을 그대로 믿음 **[중요]**
- 4-3절 루브릭은 `collinear_violations`, `point_count` 같은 **값을 읽어** 채점함.
- 체크섬의 솔트는 공개 저장소 코드에 있으므로, 마음먹은 학생은 값을 고치고 체크섬도 다시 만들 수 있음.
- 대안: 채점은 **원자료(점 좌표, 조립한 식)에서 다시 계산**. 선언형 규칙(`field`/`op`)만으로는 다시 계산을 할 수 없음 → 3절 대안 B1.

### C4. 서술형 "20자 이상이면 20/30점" 자동 부여
- 4-3절 `manual_with_auto_check`: 글자 수만 넘기면 서술형 배점의 2/3를 받음.
- 학생이 아무 문장이나 채우는 동기가 생기고, 평가 타당성 설명이 어려움(교육자료전 심사에서도 약점).
- 대안: 글자 수는 "미작성/작성" 표시만 하고 점수는 교사가 매김.

### C5. 논문 내용 설명에 사실과 다르거나 출처 없는 문장
| 위치 | 초안 문장 | 문제 |
|---|---|---|
| 7-1 | "n > 46일 때 왜 2n개 배치가 깨지는지" | 2n개 배치가 n이 커지면 불가능하다는 것은 **추측**이지 증명된 사실이 아님. 2n개 배치가 알려진 범위도 논문으로 확인 필요 |
| 4-1 `story` | "100년 넘게 손으로 찾던 문제를 AI가 새로운 해를 찾아냈다" | 논문이 실제로 무엇을 새로 찾았는지 원문 확인 필요. 과장 위험 |
| 4-1 `paper.authors` | "Charton et al." | 출처 확인 필요 (논문 페이지에서 확인 후 기입) |
| 7-2 | "1969년 이후 50년간 멈춰 있던 기록을 AlphaTensor가 해결" | 2×2는 7번이 최소임이 이미 증명됨(Winograd, 1971). AlphaTensor의 개선은 4×4 **mod 2** 등 특정 경우. 학생이 "2×2를 AI가 더 줄였다"고 오해할 수 있음 |
| 7-2 | "스마트폰 그래픽과 AI 연산의 90%는 행렬 곱셈" | 출처 없는 수치. 빼거나 "대부분" 정도로 |
- 제안: 각 모듈 `guide.md`에 **"사실–출처 표"**를 두고, 출처 없는 문장은 화면에 올리지 않는 규칙.

### C6. 모듈 목록: 손으로 한 줄 추가 vs 자동 생성이 섞여 있음
- 3절은 "`registry.json`에 한 줄 추가 또는 Action 자동 갱신", 11절은 "한 줄 추가".
- 손으로 추가하는 방식은 "폴더 하나 + 메타데이터 하나"(BRIEF 5-4)보다 한 단계 많고, 빠뜨리면 모듈이 안 보임.
- 대안: Actions에서 `module.json`을 모아 자동 생성 (검사 스크립트와 한 번에 실행).

### C7. localStorage 자동 저장 — 공용 PC 개인정보
- 학교 컴퓨터실 PC는 여러 학생이 같이 씀. 이름·답안이 남으면 다음 학생이 볼 수 있음 (BRIEF 5-2 취지와 충돌).
- 대안: 자동 저장은 하되 **이름·학번은 저장하지 않음**, 결과물 다운로드 후 "기록 지우기" 안내, 저장 기간 제한(예: 당일).

### C8. 오프라인 zip 번들은 파일을 더블클릭으로 열면 동작하지 않음
- ES 모듈 `import`와 `fetch('module.json')`은 `file://`로 열면 크롬에서 막힘.
- 따라서 "zip 받아서 열기"는 별도 로컬 서버가 필요함 → 교사·심사장에서 쉽지 않음.
- 대안: 오프라인은 **PWA(Service Worker) 캐시**를 주 방법으로, 심사장용으로는 노트북에 미리 한 번 접속해 캐시해 두는 절차를 안내. (※ Claude 초안의 같은 대응안도 이 이유로 수정함 — 4절)

### C9. Service Worker를 학기 중에 쓰면 옛 버전이 남을 수 있음
- 캐시 갱신을 잘못하면 수정한 모듈이 학생 기기에 반영되지 않음 → 루브릭과 결과물 버전이 어긋남.
- 대안: 캐시 이름에 플랫폼 버전을 넣고, 새 버전이면 "새로고침" 안내 띄우기. MVP 핵심 기능이 완성된 뒤(M4) 적용.

### C10. 테스트 계획에 학생 시범 사용·접근성 점검이 없음
- BRIEF 6-4 9항은 "학생 시범 사용"을 명시함. 초안 9절에는 빠져 있음.
- 색각 배려는 설계에 있으나 검사 절차가 없음.
- 일정(8절)에 기간이 없어 교육자료전 마감에서 거꾸로 계산하기 어려움.

### C11. 평가 척도 A~C
- 2022 개정 고교 공통과목의 성취도 단계가 A~E 5단계인지 확인 필요. 맞다면 루브릭 척도도 A~E에 맞추는 게 학교 평가와 연결하기 쉬움.
- 척도와 자동 채점 비율은 요청자 결정 사항(Q3)으로 두는 데 동의.

### C12. 작은 불일치
- Q6 선택지 ①은 "CC BY-NC-SA", 권장안은 "CC BY-SA"로 서로 다름. 한쪽으로 맞춰야 함.
- 제출 코드(Base64) 복사: 점 좌표·답안이 들어가면 수천 자가 될 수 있음. 패들릿·구글 설문 칸 길이 제한을 시범에서 확인 필요.
