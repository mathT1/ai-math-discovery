## 1. 동의하는 점 (합의 완료 기반)

Claude Code의 초안은 학교 현장 환경과 교사 1인 유지보수라는 핵심 제약을 정확히 짚고 있으며, Antigravity의 초안과 핵심 설계 방향이 일치합니다. 아래 항목들은 **이견 없이 최종안에 그대로 채택**할 것을 제안합니다.

1. **기술 스택 (No-Build Vanilla JS + 로컬 KaTeX + Pyodide 배제)**
   - 빌드 도구(Vite/Webpack)와 외부 프레임워크 없이 순수 HTML/CSS/ES Modules만 사용하고, KaTeX를 `vendor/katex/`에 내장하며, 무거운 Pyodide를 배제한다는 결정과 근거가 완벽히 일치합니다.
2. **MVP 첫 모듈 2개 선정 (`no-three-in-line` + `matrix-mult`)**
   - 고1 공통과목(공통수학1·2)과 직결되고 정수 연산으로 오차 없는 판정이 가능하다는 점에서 두 에이전트의 권장안이 일치합니다.
3. **결과물 형식 및 체크섬·CSV 방식**
   - 학생 결과물로 **PNG 보고서 + JSON 채점 파일**을 기본 제공하고(PDF는 브라우저 인쇄 활용), Web Crypto API 기반 **SHA-256 체크섬**으로 단순 수정 여부를 감지하며, 교사용 CSV 내보내기에 **UTF-8 BOM**을 넣어 한글 엑셀 깨짐을 방지하는 설계에 전적으로 동의합니다.
4. **Claude 초안의 우수 아이디어 적극 수용 (Antigravity 안 보완)**
   - **`tools/build-index.mjs`를 통한 `modules/index.json` 자동 생성**: Antigravity는 `registry.json`에 수동으로 한 줄 추가하는 방식을 제안했으나, Claude의 제안처럼 스크립트/GitHub Actions가 `modules/*/module.json`을 읽어 `index.json`을 자동 생성하면 R6("폴더 하나 추가로 끝")를 완벽히 충족합니다.
   - **`module.json`의 `status: "draft" | "published"` 필드**: 제작 중인 모듈이 홈 화면에 노출되지 않게 보호하는 실용적인 장치로 적극 수용합니다.
   - **원시 데이터 재계산(Re-computation) 원칙**: 자동 채점 시 학생 JSON에 적힌 요약 점수를 그대로 믿지 않고, 제출된 점 좌표(`points[]`)나 수식 조립 상태로부터 공선 여부·정답 여부를 다시 계산한다는 원칙에 전적으로 동의합니다.
   - **개인정보 최소화 옵션**: 공개 게시판(패들릿 등) 제출 시 이름 대신 학번/번호만 적을 수 있게 안내하는 방안을 수용합니다.

## 2. 우려되는 점 (근거 포함) 및 대안

Claude 초안의 세부 설계 중 유지보수성, 학습 효과, 현장 제출 편의성 측면에서 우려되는 5가지 지점과 그에 대한 절충 대안입니다.

### 2-1. 모듈 화면 구조: 개별 `modules/<id>/index.html` vs 공통 쉘(`core/shell.js`)

- **우려되는 점 (근거)**:
  - Claude 안(4-1절)은 각 모듈 폴더마다 `index.html`을 두는 구조입니다.
  - 향후 모듈이 9개 이상으로 늘어났을 때, 공통 헤더, 4단계 수업 탭(도입 → 탐구 → AI 비교 → 정리/다운로드), 학생 정보 입력 모달, 교사용 지도안 뷰어 등의 HTML 마크업이 각 모듈의 `index.html`에 중복되면 디자인이나 공통 기능을 한 번 고칠 때 모든 모듈의 HTML 파일을 수정해야 합니다.
- **대안 (보일러플레이트 최소화 쉘 구조)**:
  - URL 라우팅 방식(`module.html?id=no-three-in-line`)을 쓰거나, 혹은 클린 URL을 위해 `modules/<id>/index.html`을 두더라도 그 안에는 **단 1줄의 `<script type="module" src="../../core/shell.js"></script>`만 두고**, 공통 헤더·탭·학생 입력 폼·결과물 내보내기 UI는 `core/shell.js`가 `module.json`과 `activity.js`를 읽어 자동으로 렌더링하게 합니다. 이렇게 하면 깔끔한 URL(`modules/no-three-in-line/`)과 유지보수성(본체 UI 수정 시 자동 반영)을 동시에 얻을 수 있습니다.

### 2-2. 자동 채점 구조: `grader.js` 함수형 vs `rubric.json` 선언형의 결합

- **우려되는 점 (근거)**:
  - Claude 안(4-1, 4-4절)은 `eval` 위험을 피하고 원시 데이터를 재계산하기 위해 모듈마다 `grader.js`를 두어 채점 함수를 호출하도록 했습니다.
  - 원시 데이터 검증(공선 재계산 등)을 JS 함수로 분리한 것은 매우 훌륭하나, **점수 구간(예: 점 12개면 3점, 10개면 2점)까지 `grader.js` 코드 안에 하드코딩되면**, 교사가 학급 수준에 맞춰 배점 기준만 살짝 바꾸고 싶을 때도 JS 코드를 수정해야 합니다.
- **대안 (하이브리드 채점 파이프라인: `grader.js` 지표 추출 + `rubric.json` 배점 매핑)**:
  - `grader.js`는 학생 `payload`를 재검증하여 **객관적 사실/수치 객체**(예: `{ valid: true, validCount: 12, targetRatio: 1.0 }`)와 근거 문장만 계산해 반환합니다.
  - `rubric.json`은 그 수치에 따라 몇 점을 부여할지 구간표(`tiers: [{ "min": 12, "score": 3 }, { "min": 10, "score": 2 }]`)를 가집니다.
  - 이렇게 분리하면 **`eval` 없이 안전하게 원시 데이터를 재검증**하면서도, **배점 조정은 `rubric.json` 숫자만 고쳐서** 해결할 수 있습니다.

### 2-3. `matrix-mult` 퍼즐의 검산 방식: 무작위 정수 행렬 검산 + 기호 다항식 소거 시각화

- **우려되는 점 (근거)**:
  - Claude 안(7-2절)은 스트라센 퍼즐에서 학생이 조립한 식의 정확성을 "기호 계산 대신 무작위 정수 행렬 여러 개로 검산"하자고 제안했습니다.
  - 채점(`grader.js`)에서는 간단하고 좋지만, **학생이 퍼즐을 푸는 화면(`activity.js`)**에서 숫자만 대입해 맞다/틀리다만 보여주면 학생은 왜 $(a_{11}+a_{22})(b_{11}+b_{22})$ 같은 식에서 불필요한 항($a_{11}b_{22}$ 등)이 다른 $M_k$ 블록과 만나 **상쇄(소거)**되는지 대수적 원리를 눈으로 볼 수 없습니다.
  - $2 \times 2$ 행렬 곱의 기호 전개는 복잡한 CAS(기호대수 라이브러리)가 전혀 필요 없으며, 가능한 16개 항($a_{ij}b_{kl}$, $i,j,k,l \in \{1,2\}$)의 정수 계수 배열(길이 16) 덧셈·뺄셈만으로 **코드 30줄 이내에 100% 정확한 기호 전개식을 구현**할 수 있습니다.
- **대안**:
  - 활동 화면에서는 길이 16짜리 계수 배열 연산을 통해 **학생이 $M_1 \sim M_7$을 더하고 뺄 때마다 우측에 기호 다항식이 전개되고 불필요한 항이 실시간으로 지워지는(소거되는) 시각적 피드백**을 제공하고, 동시에 **"내 숫자로 직접 검산해 보기"** 기능도 함께 넣어 대수적 원리와 수치 확인을 모두 잡는 것을 제안합니다.

### 2-4. 평가 척도: 성취수준형(A~E) 단독 vs 점수 + 성취수준 병행

- **우려되는 점 (근거)**:
  - Claude 안(1절 Q3, 4-4절)은 총점 10점 만점에 성취수준(A~E)을 부여하는 단일 예시를 들었습니다.
  - 고등학교 현장에서는 지필/수행평가 반영 시 100점 만점(또는 20점/30점 만점) 환산 점수가 필요한 경우와 성취수준(A~C 또는 A~E)이 필요한 경우가 혼재합니다.
- **대안**:
  - `rubric.json`의 항목별 점수를 합산한 **총점(숫자)**과 `level_cut`에 따른 **성취수준(등급)**을 평가 화면과 CSV에 **둘 다 출력**하도록 하면 교사가 학교 평가 계획에 맞춰 원하는 열(column)을 바로 쓸 수 있습니다.

### 2-5. 현장 수업 및 교육자료전 시연을 위한 보조 기능 2가지 추가 제안

- **우려되는 점 (근거)**:
  1. **태블릿 파일 첨부 병목**: 아이패드(Safari)나 공용 태블릿에서 패들릿·구글 설문지로 제출할 때 학생이 다운로드 폴더에서 `.json` 파일을 찾지 못해 수업 시간이 지연되는 일이 잦습니다.
  2. **교육자료전 현장 심사**: 심사위원이 `teacher/index.html`의 일괄 채점 기능을 확인하려 할 때, 업로드할 학생 JSON 파일이 준비되어 있지 않으면 핵심 기능을 시연하기 어렵습니다.
- **대안**:
  1. `core/export.js`에 `.png`·`.json` 다운로드 버튼 외에 **[제출용 텍스트 코드 복사]**(JSON을 압축/Base64 인코딩한 문자열) 버튼을 두고, 교사 평가 페이지에서도 파일 드래그 앤 드롭과 **코드 붙여넣기**를 모두 지원합니다.
  2. 교사 평가 페이지(`teacher/index.html`)에 **[샘플 학급 결과물(30명) 불러오기]** 버튼을 기본 탑재하여, 교사 연수나 교육자료전 심사에서 클릭 한 번으로 자동 채점·위변조 감지·CSV 다운로드 전 과정을 즉시 체험할 수 있게 합니다.

| 성취기준 표기 | 웹 검색 결과를 바탕으로 "검증 완료"로 표기 | 공식 교육부 고시 원문(NCIC/교육부 고시 제2022-33호 별책8 쪽수 포함) 대조 전까지 **"후보 (원문 쪽수 확인 필요)"**로 보수적 표기 | BRIEF 4절("실제 문서로 확인") 및 출처 명확성 원칙 준수 |
| 공용 PC `localStorage` | 활동 내용 전체 자동 저장 | 활동 상태만 당일 임시 저장하되 **학번·이름은 절대 저장하지 않음** + [초기화] 버튼 제공 | 컴퓨터실 공용 PC에서 앞 시간 학생의 이름이 남는 개인정보 문제 해결 |
