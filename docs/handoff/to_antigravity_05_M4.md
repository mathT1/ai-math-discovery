## 1. M4에서 만든 것

| 파일 | 내용 |
|---|---|
| `tools/sw-template.js` | Service Worker 틀. 사이트 파일 전체를 미리 저장하고 캐시를 먼저 씀. 이전 버전 캐시 삭제. STATUS 메시지에 응답 |
| `tools/build-index.mjs` | 기존 검사에 더해 `/sw.js` 생성: 파일 목록 + 버전(`플랫폼 버전-내용 해시`). `sw.js`는 저장소에 올리지 않고 Actions에서 매번 생성 |
| `core/offline.js` | 등록, 상태 표시("✔ 인터넷 없이 쓸 준비 완료"), 새 버전 [새로고침] 안내, `?sw=1`(미리보기에서 켜기), `?nosw`(해제·캐시 삭제) |
| `index.html`, `teacher.html`, `guide.html`, `core/home.js`·`teacher.js`·`shell.js` | 오프라인 연결과 상태 표시 칸 |
| `tools/make-samples.mjs` → `samples/*.json` | 모듈마다 30명. 고정 씨앗으로 생성. 체크섬은 학생 화면과 같은 방식. 1~20번은 교사 점수까지 채움 |
| `core/teacher.js` | 샘플 형식 `{ result, teacher }` 지원(일반 결과물도 그대로 됨). 실패 메시지를 404와 그 밖의 오류로 나눔 |
| `core/ui.css` | 교사 표에서 반·번호·이름·버튼이 한 글자씩 세로로 쪼개지던 문제 수정. 새 버전 안내 막대 |
| `tests/samples.test.mjs` | 샘플 검사: 형식, 체크섬, 다시 계산, 교사 점수가 levels 안에 있는지, 성취수준 분포 |
| `tests/e2e-offline.mjs` | **서버를 실제로 끄는** 오프라인 종단 테스트 |
| `docs/DEVICE_CHECK.md` | 요청자용 기기 점검표, 현장 시연 절차(7분), 결과 기록표 |

## 2. 검토해 주실 것

### ① 오프라인 설계 (`tools/sw-template.js`, `core/offline.js`)
- 캐시 우선 + 내용 해시 버전 방식에서 **옛 파일이 섞이거나 갱신이 안 되는 경우**가 있는지
  - 설치 시 `cache: 'reload'`로 받음
  - `ignoreSearch`로 주소 뒤 조건(`?drafts`, `?id=`, `?submit=`)을 무시함
- 업데이트를 [새로고침]을 누를 때만 적용하는 정책이 수업 현장에 맞는지
- 개인정보 원칙: 캐시에는 사이트 파일만 들어가고, 학생 결과물이나 이름은 들어가지 않음

### ② 샘플 데이터 (`samples/*.json`, `tools/make-samples.mjs`)
- 답안 문장과 미리 채운 교사 점수가 rubric levels 문구와 맞는지 (예: 30점 답이 30점 기준을 실제로 충족하는지)
- 분포가 연수·시연에 적절한지. matrix-mult에 E가 9명으로 많은 편인데, 조정이 필요한지
- 이름 `샘플 01`, 반 `1-3` 방식에 문제가 없는지

### ③ 기기 점검표·시연 절차 (`docs/DEVICE_CHECK.md`)
- 교사가 혼자 따라 할 수 있는지, 빠진 항목은 없는지 (예: 학교에서 많이 쓰는 웨일 브라우저, 크롬북 관리 정책)
- 7분 시연 순서가 심사에 효과적인지

### ④ 전체 최종 점검
- 금지 문장 6개가 어디에도 없는지 (FACT_SOURCES 5절)
- README의 현재 상태 설명이 정확한지
- 출품 전에 꼭 고쳐야 할 것이 있다면 **중요도 순서로** 적어 주세요.
