- 위 6×6 배치(12개)는 3점 조합 220개를 모두 검사해 **공선 0개임을 확인**한 실제 해입니다 [P2].

- 체크섬은 `meta`+`student`+`payload`+`reflections`를 정해진 순서로 직렬화해 SHA-256으로 만듭니다. 고친 파일을 "수정 감지"로 표시만 합니다 [D14].

### 4-5. 채점: grader.js → rubric.json [D10·D11]

**grader.js**: 원자료로 다시 계산해 지표와 근거를 반환합니다.
```js
export function metrics(payload) {
  // 예: { collinearTriples: 0, pointCount: 12, ratio: 1.0 }, evidence: ["공선 3점 없음"]
}
```

**rubric.json**: 지표를 점수로 바꾸는 구간표와 교사 항목입니다. 코드나 `eval` 없이 숫자만 고칩니다.
```json
{
  "scale": ["A", "B", "C", "D", "E"],
  "level_cut": { "A": 90, "B": 80, "C": 70, "D": 60 },
  "items": [
    { "id": "valid", "label": "규칙 준수", "type": "auto", "metric": "collinearTriples",
      "tiers": [{ "max": 0, "score": 20 }], "max": 20 },
    { "id": "count", "label": "점 개수(2n 대비)", "type": "auto", "metric": "ratio",
      "tiers": [{ "min": 1.0, "score": 20 }, { "min": 0.8, "score": 12 }, { "min": 0.6, "score": 6 }], "max": 20 },
    { "id": "q1", "label": "공선 판정 설명", "type": "teacher", "question": "q1", "max": 30,
      "levels": { "30": "판정식을 세우고 이유를 설명", "20": "판정식만 제시", "10": "예시로만 설명", "0": "미작성" } },
    { "id": "q2", "label": "2n 상한 설명", "type": "teacher", "question": "q2", "max": 30,
      "levels": { "30": "한 행에 2개 이하임을 근거로 설명", "15": "부분적 설명", "0": "미작성" } }
  ]
}
```
- 위 예시는 자동 40 : 교사 60 (U3 기본값)입니다.
- 교사 항목은 자동으로 점수를 주지 않습니다. "작성/미작성" 표시만 합니다 [D11].
- `level_cut` 값은 예시이며, U3 결정 후 확정합니다.

## 5. 결과물 다운로드 형식과 평가 흐름

**학생**
1. 모듈 열기 → 활동. 진행 상태는 당일만 임시 저장되고, 이름·학번은 저장하지 않습니다. [초기화] 버튼이 있습니다 [D16].
2. 정리 질문에 답한 뒤 반·번호(이름은 선택)를 입력합니다.
3. 버튼 3개(아이패드 연속 다운로드 차단 대비로 분리):
   - **① 보고서 저장(PNG)**
   - **② 제출 파일 저장(JSON)**
   - **③ 제출 코드 복사** [D20]
4. 파일명: `<모듈id>_<반>-<번호>_<이름>.json/.png`
5. 제출 방법을 골라 제출합니다(5-1절).

PNG 보고서 내용: 학생 정보, 활동 그림, 핵심 수치(다시 계산한 값), 정리 질문 답, AI 결과 비교 한 줄, 생성 시각.

**교사 (`teacher.html`, 모든 처리는 교사 브라우저 안에서)**
1. 모듈 선택 → JSON 여러 개 끌어다 놓기 또는 제출 코드 붙여넣기.
2. 형식 검사 → 체크섬 확인("수정 감지" 배지) → 같은 학생 중복 제출 표시.
3. 자동 항목: `grader.js`로 다시 계산해 점수와 근거를 표시합니다.
4. 교사 항목: 서술형 답을 표에서 읽고 `levels`를 클릭해 채점합니다.
5. CSV 다운로드(UTF-8 BOM): 반, 번호, 이름, 항목별 점수, **총점, 성취수준**, 서술형 원문, 체크섬 상태 [D15·D22].
6. **[샘플 학급 30명 불러오기]**: 연수·심사용 [D19].

### 5-1. 제출 방법 선택 (U4)

학생 화면의 마지막 단계에서 4가지 중 하나를 고릅니다. 교사가 링크에 `?submit=classroom`처럼 붙여 공유하면 그 방법이 미리 선택됩니다. 학생이 다른 방법으로 바꿀 수도 있습니다.

| 방법 | 학생 화면에 나오는 것 | 교사가 하는 일 | 비고 |
|---|---|---|---|
| **구글 클래스룸** | ① PNG 저장 ② JSON 저장 + "과제에 두 파일 첨부" 안내 | 클래스룸에서 제출물 내려받기 → 압축 풀기 → `teacher.html`에 JSON 끌어다 놓기 | 자동 채점 가능 |
| **패들릿** | ① PNG 저장 ② **제출 코드 복사** + "게시물에 그림 올리고 코드 붙여넣기" 안내. **이름 칸은 기본으로 숨김**(번호만) | 게시물의 코드를 복사 → `teacher.html`에 붙여넣기(여러 개는 줄마다 하나씩) | 공개 게시판이라 이름 제외. 코드 길이는 시범 수업에서 확인 [D20] |
| **메일** | ① PNG 저장 ② JSON 저장 ③ **메일 제목 복사**(`[모듈명] 1-5 12번 홍길동`) | 첨부파일을 한 폴더에 저장 → 끌어다 놓기 | 메일 주소는 교사가 수업에서 안내(플랫폼에 저장하지 않음) |
| **출력물** | A4 1장 **인쇄용 보고서**(학생 정보, 활동 그림, 핵심 수치, 정리 답, 교사 채점란) | `teacher.html`의 **[수기 입력]** 모드: 반·번호를 적고 루브릭 항목별 점수를 클릭 | 원자료 재계산은 불가 → 자동 항목도 교사가 보고서를 보고 확인. 결과는 같은 CSV로 나옴 |

- 어떤 방법이든 결과는 **하나의 CSV**로 모입니다. 한 학급 안에서 방법이 섞여도 됩니다.
- 플랫폼은 메일을 보내거나 파일을 올리지 않습니다. 저장·복사·인쇄만 하고, 제출은 학생이 직접 합니다(BRIEF 5-2).

## 7. 모듈별 상세 설계

공통 규칙: 화면에 나오는 수학적 사실과 논문 설명은 모두 `guide.md` "사실–출처 표"에 출처(논문 절·쪽, 교과서)가 있어야 합니다. 없으면 싣지 않습니다 [P1].

### 7-1. `no-three-in-line` (1차시, 공통수학2 도형의 방정식)

- **성취기준** (확인됨, 공통과목 성취수준 PDF)
  - `[10공수2-01-02]` 두 직선의 평행 조건과 수직 조건을 탐구하고 이해한다. (PDF 119쪽) — 세 점 A, B, C가 한 직선 위에 있다 ⇔ 직선 AB와 BC의 기울기가 같다(평행 조건 + 공통점 B)
  - `[10공수1-03-01]` 합의 법칙과 곱의 법칙을 이해하고, 적절한 전략을 사용하여 경우의 수와 관련된 문제를 해결할 수 있다. (PDF 38쪽) — 확인해야 할 세 점 조합의 수, 최대 개수 추론
  - 참고: 2022 개정 공통수학2 도형의 방정식에는 "직선의 방정식" 단독 성취기준이 없음(10공수2-01-01~07 확인).
- **학습 목표**
  1. 세 점이 한 직선 위에 있는지 좌표로 판정할 수 있다.
  2. n×n 격자에서 조건을 지키며 점을 배치하고, 최대 개수가 2n 이하인 이유(한 행에 최대 2개)를 설명할 수 있다.
  3. 사람의 탐색과 AI 탐색의 차이를 말할 수 있다.
- **활동 흐름 (50분)**

| 단계 | 시간 | 내용 |
|---|---|---|
| 도입 | 5분 | 3×3, 4×4에서 손으로 시도. "최대 몇 개?" |
| 탐구 | 20분 | n=3~8 보드. 점을 놓으면 공선이 되는 세 점과 직선을 **선 모양·× 기호·번호 배지**로 표시(색만 쓰지 않음). 판정식 (x₂−x₁)(y₃−y₁) = (y₂−y₁)(x₃−x₁): 정수 계산이라 오차가 없음 |
| AI 비교 | 15분 | 같은 n의 2n개 배치(data/)와 비교. 논문 결과(초록 기준): 고전 방법 ILP는 19×19까지 최적임을 증명, PatternBoost는 14×14까지 최적과 같은 결과, PPO는 10×10까지 완벽하지만 11×11에서 실패. 핵심 메시지: "AI는 작은 격자에서 경쟁력이 있고, 정확한 답에는 고전 방법이 여전히 필요하다". 이 논문은 새 기록이 아니라 **방법 비교** 논문임. **"n이 크면 2n개가 불가능하다"는 증명된 사실이 아니라 추측으로 소개** [P1] |
| 정리 | 10분 | q1, q2 답 작성 → 결과물 저장 |

- **결과물 payload**: `n`, `points[]`
- **지표(grader.js)**: `collinearTriples`, `pointCount`, `ratio = pointCount / 2n`
- **루브릭**: 4-5 예시 그대로 (규칙 준수 20, 개수 20, q1 30, q2 30)
- **데이터**: n=3~8의 2n개 배치는 sandbox에서 직접 탐색해 만들고, 논문·참고 코드 결과와 대조합니다. 모두 `tests/`에서 공선 0을 확인합니다.
- **예상 오개념**: 가로·세로·대각선만 확인하고 기울기 1/2, 2/3 같은 직선을 놓침 → 탐구 단계에서 "기울기 레이더" 힌트로 짚어 줌.

### 7-2. `matrix-mult` (1~2차시, 공통수학1 행렬)

- **성취기준** (확인됨, 공통과목 성취수준 PDF)
  - `[10공수1-04-02]` 행렬의 연산을 수행하고, 관련된 문제를 해결할 수 있다. (PDF 15·16·39쪽)
  - 성취기준 해설(PDF 16쪽): "행과 열의 수가 각각 2를 넘지 않는 범위에서 행렬의 곱셈을 할 수 있게 한다" → **활동은 2×2로 한정**. 4×4·5×5 결과는 계산시키지 않고 이야기로만 소개.
- **학습 목표**
  1. 2×2 행렬의 곱을 계산하고, 일반 방법에서 곱셈이 8번 필요함을 센다.
  2. 덧셈·뺄셈을 늘리는 대신 곱셈을 7번으로 줄이는 방법(스트라센)을 전개와 소거로 확인한다.
  3. AI(AlphaTensor)가 "곱셈 횟수 줄이기"를 게임처럼 탐색했다는 것을 설명할 수 있다.
- **확인된 식** (16칸 계수 배열 전개로 네 성분 모두 검증함 [P2])
  - M₁=(a₁₁+a₂₂)(b₁₁+b₂₂), M₂=(a₂₁+a₂₂)b₁₁, M₃=a₁₁(b₁₂−b₂₂), M₄=a₂₂(b₂₁−b₁₁),
    M₅=(a₁₁+a₁₂)b₂₂, M₆=(a₂₁−a₁₁)(b₁₁+b₁₂), M₇=(a₁₂−a₂₂)(b₂₁+b₂₂)
  - c₁₁=M₁+M₄−M₅+M₇, c₁₂=M₃+M₅, c₂₁=M₂+M₄, c₂₂=M₁−M₂+M₃+M₆
- **활동 흐름**

| 단계 | 내용 |
|---|---|
| 도입 | 일반 방법으로 곱하며 곱셈 횟수 세기(8번) |
| 워밍업 | (a+b)(c+d) 같은 곱을 더하고 빼서 원하는 항만 남기는 미니 퍼즐 |
| 본 활동 | M₁~M₇ 블록을 더하고 빼서 c₁₁~c₂₂ 만들기. 블록을 바꿀 때마다 전개식이 표시되고 지워지는 항이 보임 [D12]. 난이도: 빈칸 채우기 / 직접 조합. 보조: "내 숫자로 검산" |
| AI 비교 | ① 2×2는 7번이 최소임이 증명되어 있음(Winograd, 1971) → AI도 2×2는 못 줄임. ② AlphaTensor(Fawzi 외, *Nature* 610, 47–53, 2022): 4×4 행렬을 **mod 2 계산**에서 곱셈 47번으로(스트라센 2번 적용 시 49번), 5×5도 mod 2에서 96번으로(기존 98번). 70개가 넘는 크기에서 기존 최고 기록 개선. ③ 방법: 곱셈 방법 찾기를 "블록 지우기 게임"으로 바꾸고, 바둑 AI(AlphaZero) 방식의 강화학습으로 탐색. ④ 주의: 4×4 47번은 실수 계산이 아니라 mod 2에서만 성립 [P1] |
| 정리 | "덧셈이 늘었는데 왜 이득일까?" (큰 행렬로 갈수록 차이가 커진다는 직관만. log₂7 지수는 보충) |

- **결과물 payload**: 성분별로 고른 M 조합 계수(예: `c11: [1,0,0,1,-1,0,1]`), 사용한 곱셈 수
- **지표(grader.js)**: `correctEntries`(0~4, 계수 전개로 판정), `multiplications`
- **루브릭(초안)**: 정확한 성분 수(자동 30), 곱셈 7번 달성(자동 10), "왜 이득인가" 설명(교사 30), AI 비교 설명(교사 30)
- **R7 주의**: 텐서, 랭크 같은 용어는 쓰지 않거나 "블록 조립 횟수"로 바꿔 씀.

## 10. GitHub 배포·버전 관리 [D18]

- 공개 저장소, `main` 브랜치 하나.
- push하면 Actions가 `node tools/build-index.mjs`와 `node --test`를 실행합니다. 실패하면 배포하지 않고, 통과하면 Pages에 배포합니다.
- 플랫폼 버전은 태그(`v1.0.0` MVP, `v1.1.0` 모듈 추가)로 붙이고, 모듈 버전은 `module.json`의 `version`으로 관리합니다.
- Service Worker 캐시 이름에 플랫폼 버전을 넣고, 새 버전이면 "새로고침" 안내를 띄웁니다 [D17].
- 학기 중에는 사용 중인 모듈의 결과물 형식을 깨는 변경을 하지 않습니다. 바꿔야 하면 새 버전으로 추가합니다.

## 11. 새 모듈 추가 절차 (`docs/CONTRIBUTING_MODULE.md` 초안)

1. `modules/_template/`을 `modules/<id>/`로 복사합니다(`status: "draft"`).
2. `module.json`을 씁니다. 성취기준은 출처와 쪽수가 있을 때만 확정 코드로 적습니다.
3. `activity.js`에 표준 함수 4개를 작성합니다.
4. `grader.js`(지표), `rubric.json`(구간표), `schema.json`을 작성합니다.
5. `guide.md`: 차시 흐름, 발문, 예상 오개념, **사실–출처 표**를 작성합니다.
6. `data/`를 검증하는 테스트를 `tests/`에 추가합니다.
7. `node tools/build-index.mjs && node --test`로 확인합니다.
8. `status: "published"`로 바꿔 push하면 홈과 평가 페이지에 자동 반영됩니다.

본체(`core/`, `index.html`, `teacher.html`)는 고치지 않습니다. 고쳐야 한다면 표준에 빈틈이 있다는 뜻이므로 따로 기록합니다.

## 13. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 성취기준 코드 오기 | 출처·쪽수 없으면 "후보(확인 필요)", 검사 스크립트가 차단 [D21] |
| 논문 내용 과장·오해 | 사실–출처 표, 출처 없는 문장 금지 [P1] |
| 틀린 예시·데이터 | 모든 데이터·예시 자동 재검증 [P2] |
| 학생이 JSON 조작 | 원자료 재계산 채점 + 체크섬 수정 감지 [D10·D14] |
| 서술형 점수 남용 | 서술형은 교사만 채점 [D11] |
| 공용 PC에 개인정보 남음 | 이름 저장 안 함, 당일만, 초기화 버튼 [D16] |
| 학교망 CDN·사이트 차단 | 외부 파일 없음, M0에 학교 PC 접속 확인 |
| 태블릿 다운로드 문제 | 버튼 분리, 제출 코드 보조, 기기별 저장 안내 |
| 옛 버전 캐시 | 버전 이름이 붙은 캐시 + 새로고침 안내 [D17] |
| 참고 코드·데이터 라이선스 | 가져오기 전 확인, 불명확하면 직접 생성 |

| 교사 1인 유지보수 | 빌드 없음, 외부 의존 최소, 모듈 독립(하나가 고장 나도 다른 모듈은 영향 없음) |
